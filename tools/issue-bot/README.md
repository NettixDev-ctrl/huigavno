# Бот задач mokaGram

Отдельный Telegram-бот для чата разработки. Он превращает описание в черновик задачи для `mokagram/mokagram`. Автор запроса проверяет заголовок, текст и метки, затем нажимает «Создать issue» или «Отменить». После публикации бот показывает номер и ссылку в той же теме чата.

## Как вызвать

- `@имя_бота На macOS пропадает панель очереди после сворачивания #bug`
- `/issue@имя_бота Добавить настройку размера обложки #enhancement`
- Ответьте на сообщение с требованиями командой `/issue@имя_бота` или упоминанием. В том же ответе можно дописать требования.

Хештеги в запросе задают существующие метки GitHub. Для пробелов используйте подчёркивание, например `#good_first_issue`. Если метки не указаны, модель может предложить `bug`, `enhancement`, `documentation` или `accessibility`, если они есть в репозитории. Когда требований недостаточно, бот попросит уточнение. Дополните описание и вызовите его снова.

В OpenAI отправляются текст запроса и текст или подпись сообщения, на которое он отвечает. Они могут содержать внутреннюю информацию. Перед подтверждением проверьте черновик: задачи в `mokagram/mokagram` публичны. Вложения и остальная переписка не используются.

## Запуск

1. Администратор репозитория включает Issues в **Settings → General → Features**.
2. Создайте отдельного бота через [BotFather](https://t.me/BotFather) и добавьте его в чат разработки. Команды вида `/issue@имя_бота` работают с включённым Privacy Mode. Для обычных упоминаний `@имя_бота` отключите Privacy Mode через `/setprivacy` и повторно добавьте бота в группу. Права администратора в Telegram не требуются.
3. На сервере с Python 3.9+ задайте переменные окружения через хранилище секретов сервиса. Зависимостей Python сверх стандартной библиотеки нет.

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен отдельного бота |
| `TELEGRAM_DEV_CHAT_ID` | Отрицательный числовой ID группы или супергруппы |
| `GITHUB_TOKEN` | Fine-grained token для целевого репозитория с правом **Issues: Read and write**. Для назначения меток у владельца токена должен быть доступ на запись в репозиторий. |
| `OPENAI_API_KEY` | Ключ проекта OpenAI API |
| `TELEGRAM_ALLOWED_USER_IDS` | Необязательные числовые ID участников через пробел. По умолчанию запросы доступны участникам группы. |
| `OPENAI_MODEL` | Модель с поддержкой Structured Outputs. По умолчанию `gpt-5-mini`. |
| `GITHUB_REPOSITORY` | Целевой репозиторий. По умолчанию `mokagram/mokagram`. |
| `ISSUE_BOT_DB` | Путь к файлу SQLite. По умолчанию `issue-bot.sqlite3` в рабочем каталоге. |

Из корня репозитория:

```sh
python3 tools/issue-bot/bot.py --check
python3 tools/issue-bot/bot.py
```

Первая команда проверяет доступ к чату, отсутствие webhook и доступ на чтение меток в репозитории с включёнными Issues. Работу модели и публикацию проверяют отдельным запросом в тестовой группе. Запускайте один процесс на токен бота и храните файл SQLite на постоянном диске. Он сохраняет неподтверждённые черновики и результаты публикаций между перезапусками. Если GitHub не подтвердил результат создания, бот попросит проверить список Issues перед повторным запросом.

Локальная проверка с подменой внешних API:

```sh
python3 -B -m unittest discover -s tools/issue-bot
```
